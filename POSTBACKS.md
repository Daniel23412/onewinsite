# Подключение уведомлений

Прокладка может зарегистрировать нажатие на кнопку перехода. Регистрацию и депозит видит партнёрская платформа: именно она должна отправить серверный запрос в `/api/postback`. Без настройки в партнёрском кабинете уведомления о регистрациях и депозитах не появятся.

## 1. Установите секреты на сервере

В переменные окружения хостинга добавьте `BOT_TOKEN`, `POSTBACK_LOG_CHAT_ID`, `POSTBACK_SECRET` со значениями из чата. В репозиторий секреты намеренно не включены. Дайте боту право писать в ваш канал и выполните Redeploy.

## 2. Согласуйте параметр клика

При нажатии на карточку посетитель проходит через `/api/go?game=...&lang=...`. Сервер создаёт короткий подписанный `Click ID` и добавляет его к партнёрской ссылке в параметре **`sub1`**. Остальные параметры ссылки сохраняются.

В `public/site-config.json` параметр можно изменить через `clickIdParameter`, если партнёрка использует другое имя. У менеджера партнёрки нужно подтвердить, что их короткая ссылка сохраняет этот параметр и кабинет возвращает его в callback. Автоматически проверить внутренние настройки партнёрки через GitHub невозможно.

## 3. Настройте callback в партнёрке

Используйте реальный HTTPS-домен опубликованного сайта. Ниже `ВАШ_СЕКРЕТ` и значения в фигурных скобках — **шаблоны**, не реальные макросы вашей платформы. Подставьте поддерживаемые партнёркой макросы; не вставляйте шаблон без замены.

Регистрация:

```text
https://ВАШ-ДОМЕН/api/postback?secret=ВАШ_СЕКРЕТ&event=registration&event_id={УНИКАЛЬНЫЙ_ID_РЕГИСТРАЦИИ}&click_id={СОХРАНЁННЫЙ_SUB1}
```

Первый депозит:

```text
https://ВАШ-ДОМЕН/api/postback?secret=ВАШ_СЕКРЕТ&event=first_deposit&event_id={ID_ТРАНЗАКЦИИ}&click_id={СОХРАНЁННЫЙ_SUB1}&amount={СУММА_ДЕПОЗИТА}&currency={КОД_ВАЛЮТЫ}
```

Каждый следующий депозит:

```text
https://ВАШ-ДОМЕН/api/postback?secret=ВАШ_СЕКРЕТ&event=deposit&event_id={ID_ТРАНЗАКЦИИ}&click_id={СОХРАНЁННЫЙ_SUB1}&amount={СУММА_ДЕПОЗИТА}&currency={КОД_ВАЛЮТЫ}
```

`event_id` обязан быть стабильным при повторной отправке одного события. Для депозитов используйте ID отдельной транзакции, а не пользователя. Сумма — с точкой, без разделителей тысяч. Валюта — трёхбуквенный код, например `USD`, `PHP`, `IDR`, `COP`, `PEN`, `NGN` или `RUB`.

`click_id` необязателен: если партнёрка его не передаёт, уведомление придёт с пометкой «партнёр не передал», без привязки к клику. Если передан, подпись проверяется; повреждённый ID отклоняется. Подписанные клики действительны 180 дней. Смена ключа подписания делает старые ID недействительными.

Поддерживаются `GET`, `POST application/json` и `POST application/x-www-form-urlencoded`. Предпочтительно передавать секрет в заголовке **`X-Postback-Secret`** или `Authorization: Bearer ...`, если кабинет это позволяет: секрет тогда отсутствует в URL и стандартных журналах URL.

| Поле | Поддерживаемые варианты |
| --- | --- |
| Тип события | `event` или `type` |
| Регистрация | `registration`, `register`, `reg`, `lead` |
| Депозит | `deposit`, `dep` |
| Первый депозит | `first_deposit`, `ftd`, `fd` |
| ID события | `event_id`, `transaction_id`, `order_id` |
| ID клика | `click_id`, `clickid`, `sub1` или ваш `clickIdParameter` |
| Сумма | `amount`, `sum` |
| Валюта | `currency` |

Если есть поле `status`, уведомления отправляются только для `approved`, `success`, `confirmed`, `completed`, `ok`. Остальные статусы возвращают `200` с `ignored: true` и не вызывают уведомление. Если платформа использует другие значения, сначала согласуйте соответствие.

## 4. Ответы и повторная доставка

| HTTP | Значение |
| --- | --- |
| `200 {"ok":true}` | Telegram подтвердил отправку |
| `200` с `duplicate:true` | Такое событие уже обработано |
| `200` с `ignored:true` | Неподтверждённый статус; уведомление не отправлено |
| `400` | Ошибка полей, суммы, валюты или подписи клика |
| `401` | Неверный секрет |
| `413` / `415` | Слишком большое тело запроса / неподдерживаемый формат |
| `502` | Telegram не подтвердил доставку; партнёрке нужно повторить запрос |
| `503` | Не настроен сервер, событие обрабатывается или недоступно хранилище; требуется повтор |

При сбое Telegram переход посетителя всё равно выполняется. Уведомления о кликах — с ограничением частых запросов и без гарантии доставки; они не являются точной системой аналитики. Предзагрузки и известные боты не отправляют уведомления. IP посетителей не передаются в Telegram.

### Защита от повторов на serverless-хостинге

По умолчанию защита работает только в памяти текущего экземпляра функции. После перезапуска или на другом экземпляре сообщение может повториться. Для общей защиты подключите Upstash Redis и задайте **обе** переменные:

```text
UPSTASH_REDIS_REST_URL
UPSTASH_REDIS_REST_TOKEN
```

Срок хранения обработанных ID — семь дней. Повторные запросы обрабатываются с блокировкой; `deposit` и `first_deposit` с одним ID транзакции считаются одним событием. Если настроенное хранилище недоступно, запрос не подтверждается как обработанный. Как и у обычного webhook, стопроцентная доставка ровно один раз не гарантируется при обрыве между Telegram и записью результата.

## Проверка после размещения

1. Откройте `https://ВАШ-ДОМЕН/api/health`: ответ должен содержать `{"ok":true}`. Этот маршрут проверяет доступность функции, а не токен Telegram.
2. Нажмите карточку Falling Pixage и проверьте конечный адрес и сообщение о переходе в канале.
3. В партнёрском кабинете отправьте тестовое событие регистрации, затем депозита с разными уникальными ID. Проверьте `200` и уведомления.
4. Повторите тот же ID, чтобы проверить защиту от дублей. На Vercel для устойчивой проверки используйте Redis.

Живая регистрация/депозит и доступ бота не проверены созданием исходников. Тесты проекта используют имитацию Telegram API и не посылают сообщения в реальный канал.
